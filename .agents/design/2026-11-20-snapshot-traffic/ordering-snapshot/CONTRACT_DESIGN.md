# Contratto

Le firme pubbliche interne al servizio sono nello [stub](postgres-repository.stub.ts) e nei [tipi del servizio](../../../../services/checkout-api/src/ordering-contract.ts). Il repository prende un pool `pg` con lo [schema corrente](../../../../services/checkout-api/src/schema.sql) applicato. `transact` esegue la callback una volta sotto lock; restituisce un valore staccato o propaga l'errore, senza commit di modifiche parziali. Aggiornamenti tramite il precedente adattatore con `UPDATE individual_ordering_state SET snapshot = $1, updated_at = now() WHERE id = 1` restano osservabili dalle istanze correnti. Si può leggere `updated_at` per verificare l'assenza di riscritture a stato invariato. Ad esempio uno storico con campi estesi e `cursor=9` deve restare identico alla prima lettura; un retry con `cursor` invariato e un nuovo elemento nei permessi deve leggere quel permesso alla transazione successiva.

La misura usa `PIZZAOS_TEST_DATABASE_URL` con database `pizzaos_individual_test`. Il benchmark richiede loopback e usa il protocollo senza TLS per isolare e confrontare le stesse operazioni. Il riferimento riproduce il percorso precedente sullo stesso schema di prova, per ogni transazione `BEGIN`, `INSERT INTO individual_ordering_state (id, snapshot) VALUES (1, $1) ON CONFLICT (id) DO NOTHING` con stato iniziale, `SELECT snapshot FROM individual_ordering_state WHERE id = 1 FOR UPDATE`, callback, `UPDATE individual_ordering_state SET snapshot = $1, updated_at = now() WHERE id = 1` con stato aggiornato, `COMMIT`. Contare i byte di query e risposte, riportando separatamente i due versi. Le prove sullo schema precedente possono usare uno spazio nomi isolato e la tabella originaria `individual_ordering_state (id integer primary key check (id = 1), snapshot jsonb not null, updated_at timestamptz not null default now())`.
